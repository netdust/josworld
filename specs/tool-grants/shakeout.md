Hunt: 5 charters · 2 confirmed · 0 not ours · 6 rejected

Charter 1, odd input on the link address (wire probes on one live link, 14 requests): the token upper-cased, one character more or less, `download/extra`, `download.pdf`, a query string, the Dutch base without a language, the English language with the Dutch base. All refused with the dead page except the query string (the live page) and a doubled slash before download (nginx merges it). The English and French bases with the Dutch grant's token answer the live page in that language.
Charter 2, odd input on the form (browser, about 20 actions): the address in mixed case with spaces around it gives the same link as lower case; tool_id changed to the front page, a missing id, letters, a negative id and another published tool; a double click on submit; back, forward and reload after the redirect. Refusals show "nog niet beschikbaar" and make no grant; the negative id resolves to the same tool; one grant and one mail for the double click.
Charter 3, state after re-entry (about 15 actions): the editor revokes, then "Opnieuw toelaten"; the tool unpublished and published again under a live link; reloads counted. The unpublished tool's link is dead with no way back, alive again after publishing; "Keer geopend" counts GETs, not HEADs.
Charter 4, a first-time visitor at 375 px (about 10 actions): the file link, the app link and the dead page. Nothing scrolls sideways, the Download button sits inside the screen, the app renders; the app's own links point at the home page, /gratis-aanbod/ and /contact, none at the removed /tool-app/ route; the external link tool's Open button carries rel noreferrer.
Charter 5, numbers and copy on the editor screens (about 15 actions): the panel's columns and the media library item. Found rows 20 and 21.
rejected: the English and French link bases open a Dutch grant (charter 1) — baseline's `route_languages` routes one token under every language base; the token, not the prefix, is the access, and the tool shown is the one granted.
rejected: the French dead page's title reads "Page not found" in English — the local site has no French WordPress language pack; the page body is French from `labels_i18n`.
rejected: the English link and dead pages carry the Dutch newsletter footer — site content: every /en/ page has the same Dutch footer, untouched by this branch.
rejected: "Te veel aanvragen." after the sixth form in thirty seconds — FluentForm's own per-address limit (five submissions per thirty seconds), met by my rapid local probes.
rejected: "Opnieuw toelaten" leaves the old link dead — baseline's `allowAgain()` mints a new address on purpose; the visitor gets it by filling in the form again.
rejected: the local link-kind fixtures 578 and 579 show no download form — seed data: their content is empty, while every real tool carries the form in its content.
